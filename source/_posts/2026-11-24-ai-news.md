今日值得关注的动态集中在开源模型能力跃迁、推理基础设施重构与端侧部署落地三个方向，以下为精选的 4 条。

## 1. DeepSeek 开源 V3 后续版本并放出完整技术报告

DeepSeek 发布 V3 系列新版本权重，同步公开训练细节与 MoE 路由策略的技术报告，披露了 FP8 混合精度训练与负载均衡损失的工程实现。要点在于：其训练成本仍显著低于同级别稠密模型，且推理侧通过 MLA（多头潜在注意力）压缩 KV Cache，直接降低了长上下文部署的显存门槛。影响分析：这进一步压低了开源社区复现前沿 MoE 架构的门槛，中小团队可基于其路由与并行策略做垂直领域微调，闭源 API 的价格锚点将继续被拉低。

## 2. 推理框架层出现面向 MoE 的调度优化，吞吐提升明显

主流推理引擎（如 SGLang / vLLM 生态）针对 MoE 模型的专家并行与动态批处理推出新调度策略，重点解决专家负载不均导致的 GPU 空转问题，通过 token 级路由感知的批处理与专家缓存复用提升吞吐。要点：MoE 推理的瓶颈正从算力转向调度与显存带宽，框架层的优化收益已可与换卡相当。影响分析：这意味着部署成本竞争的主战场从硬件转向软件栈，具备调度优化能力的团队将在同等硬件上获得数量级成本优势。

## 3. 端侧小模型密集落地，手机与 PC 本地推理成标配方向

多家厂商推进 3B 级别以下模型的端侧部署，结合量化与 NPU 加速实现本地低延迟推理，覆盖摘要、翻译、离线问答等场景。要点：端侧模型的价值不在参数规模，而在隐私、离线可用与零推理边际成本。影响分析：端侧推理将分流大量高频轻量请求，云侧 API 的定位会向复杂推理与长上下文迁移，模型厂商需重新设计云边协同的架构与商业模型。

## 4. 长上下文与检索增强的架构边界被进一步打通

新一批工作将长上下文窗口与 RAG 流水线做统一建模，尝试用稀疏注意力与分层检索降低超长文档处理的算力开销，并在部分基准上接近全注意力效果。要点：单纯堆上下文窗口的成本不可持续，检索与注意力的混合架构正成为工程共识。影响分析：企业级文档理解、代码库级问答等场景的落地成本将明显下降，RAG 系统设计需从“外挂检索”转向“模型内建稀疏检索”的范式。
