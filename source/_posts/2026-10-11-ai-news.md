各位早。今天的动态集中在模型效率的工程化突破与开源生态的实质性推进上，以下四条值得关注。

## 1. DeepSeek 开源 DeepGEMM：为 MoE 架构量身定制的 FP8 矩阵计算库

DeepSeek 在开源周期间发布了 DeepGEMM，一个专为 FP8 精度设计的通用矩阵乘法（GEMM）库，核心亮点在于同时支持稠密模型和 MoE 模型的训练与推理，且无需预编译即可在 Hopper GPU 上实现即时编译（JIT）。其性能在多种矩阵形状下超越了 NVIDIA cuBLAS 等专家调优内核，代码量却极为精简。这意味着中小团队可以在不依赖昂贵专家调优的前提下，获得接近极致的 FP8 计算效率——对 MoE 训练成本的控制具有直接价值。

## 2. 微软开源 bitnet.cpp：让 100B 参数模型跑在单颗 CPU 上

微软研究院正式开源了 bitnet.cpp，这是首个专为 1-bit 大语言模型（如 BitNet b1.58）设计的推理框架。核心数据：在 CPU 上运行 100B 参数的 BitNet 模型可达每秒 5-7 个 token 的生成速度，能耗降低至同等 FP16 模型的 1/70 至 1/80。它通过将权重压缩至三值（-1, 0, 1），从根本上改变了推理的算力需求曲线。如果这一路线持续成熟，边缘设备和低功耗场景的 LLM 部署逻辑将被重写。

## 3. Anthropic 发布 Claude 3.7 Sonnet：首个“混合推理”模型上线

Anthropic 推出 Claude 3.7 Sonnet，最大特点是同一模型同时提供标准模式和扩展思考（Extended Thinking）模式，用户可通过 API 控制模型在回答前进行多长链条的内部推理。在 SWE-bench Verified 编程基准上取得 70.3% 的成绩，刷新了非专用编程模型的纪录。混合推理的设计思路值得注意：它不再将“快思考”和“慢思考”拆成两个模型，而是让同一个模型按需分配推理深度——这可能成为下一代 LLM 产品形态的默认范式。

## 4. 阿里通义千问开源 QwQ-32B：推理能力逼近 DeepSeek-R1，参数仅 1/20

阿里发布并开源了 QwQ-32B，一个 320 亿参数的推理专用模型。在 AIME24、LiveCodeBench 等推理基准上，其表现与 671B 参数的 DeepSeek-R1 基本持平，而参数量仅为后者的约 1/20。模型权重以 Apache 2.0 协议开放，支持消费级显卡本地部署。这条动态的核心信号是：强推理能力正在从“超大参数 + 超高成本”向“中等参数 + 高质量训练数据”迁移，推理模型的部署门槛正在快速下降。

---

以上四条的共同指向很明确：**2025 年 Q1 的主线不是更大的模型，而是更高效的推理与训练路径**——FP8 计算库、1-bit 推理框架、混合推理架构、小参数强推理模型，都在从不同维度拆解“大模型必须大算力”的等式。
